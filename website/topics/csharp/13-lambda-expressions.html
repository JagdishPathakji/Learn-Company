Lambda Expressions (Pre-LINQ)

Difficulty: Beginner / Intermediate | Category: C# Fundamentals

Learning in the Correct Order

You cannot understand Lambda Expressions without first understanding Delegates. A Lambda Expression is just a shorthand way to write a Delegate. In this module, we will learn exactly what a Delegate is, why we need it, and how it evolved into the Lambda Expression we use today.

1. The Problem

Imagine we have a List of Articles in our Knowledge Base. We want to write a method that filters this list. Sometimes we want Drafts. Sometimes we want Published articles. Sometimes we want articles by a specific author.

Instead of writing 10 different methods (GetDrafts, GetPublished, etc.), what if we could write ONE method, and pass the filtering rule (a method) into it as a variable?

To pass a method as a variable, C# requires a specific type. That type is called a Delegate.

2. What is a Delegate?

What it is:A delegate is a C# type that defines what kind of method can be stored in a variable (e.g., "This variable can hold ANY method that takes an Article and returns a bool").
Why it exists:C# is strongly typed. You can't just throw code around. The compiler needs a strict contract (the delegate) to ensure the method you are passing is safe.

Here is a complete, runnable program showing exactly how a Delegate works. Read it carefully from top to bottom:

C# - Understanding Delegates
using System;

namespace KnowledgeBase 
{
    public class Article 
    {
        public string Title { get; set; }
        public bool IsPublished { get; set; }
    }

    class Program 
    {
        // 1. DEFINE THE DELEGATE (The Contract)
        // This says: "Any method that takes an (Article) and returns a (bool) can be stored here."
        public delegate bool ArticleFilterDelegate(Article article);

        // 2. CREATE A MATCHING METHOD
        // This method perfectly matches the contract above!
        static bool CheckIfPublished(Article article) 
        {
            return article.IsPublished == true;
        }

        static void Main() 
        {
            Article myArticle = new Article { Title = "C# Basics", IsPublished = true };

            // 3. ASSIGN THE METHOD TO A VARIABLE
            // We create a variable named 'myRule' of type 'ArticleFilterDelegate'
            // and we store our method inside it!
            ArticleFilterDelegate myRule = CheckIfPublished;

            // 4. EXECUTE THE VARIABLE
            // We call the variable just like a method
            bool result = myRule(myArticle); 
            
            Console.WriteLine($"Is it published? {result}");
        }
    }
}
Console Output:
Is it published? True

3. The Evolution to Lambdas

In the previous tab, we had to write a full named method (CheckIfPublished) just so we could assign it to a delegate variable. If you have 50 different filters, writing 50 separate methods is exhausting.

Over the years, C# introduced shorter and shorter ways to assign logic to a delegate. This is how we arrived at Lambda Expressions.

Step 1: C# 1.0 (Named Methods)

The old, long way we just learned.

using System;

namespace KnowledgeBase 
{
    public class Article { public bool IsPublished { get; set; } }

    class Program 
    {
        public delegate bool ArticleFilter(Article article);

        // We had to write a separate method
        static bool CheckIfPublished(Article article) {
            return article.IsPublished == true;
        }

        static void Main() 
        {
            // Assigning the named method
            ArticleFilter myRule = CheckIfPublished;
        }
    }
}

Step 2: C# 2.0 (Anonymous Methods)

Microsoft realized writing separate methods was annoying. They allowed you to write the method inline without a name.

using System;

namespace KnowledgeBase 
{
    public class Article { public bool IsPublished { get; set; } }

    class Program 
    {
        public delegate bool ArticleFilter(Article article);

        static void Main() 
        {
            // We write the logic directly into the variable using the 'delegate' keyword
            ArticleFilter myRule = delegate(Article article) {
                return article.IsPublished == true;
            };
        }
    }
}

Step 3: C# 3.0+ (Lambda Expressions)

Microsoft realized the delegate keyword and the types were too wordy. They introduced the => operator (the Lambda operator). The compiler is smart enough to figure out the types for you!

using System;

namespace KnowledgeBase 
{
    public class Article { public bool IsPublished { get; set; } }

    class Program 
    {
        public delegate bool ArticleFilter(Article article);

        static void Main() 
        {
            // The ultimate, clean Lambda Expression!
            // Read as: "Take an article, and return whether its IsPublished property is true."
            ArticleFilter myRule = article => article.IsPublished == true;
        }
    }
}

4. Lambda Syntax Variations

Depending on how much logic you need, the syntax changes slightly.

Scenario Syntax
No Parameters () => Console.WriteLine("Hello");
One Parameter
(Type Inference - clean)		 article => article.Title == "C#"
One Parameter
(Explicitly Typed - optional)		 (Article article) => article.Title == "C#"
Multiple Parameters
(Parentheses REQUIRED)		 (article, user) => article.AuthorId == user.Id
Statement Body
(Multi-line, requires {} and return)		 
article => {
    Console.WriteLine($"Checking {article.Title}");
    return article.IsPublished;
}
Common Mistake Reading => as "greater than or equal to". It is NOT >=. The => symbol explicitly means "lambda operator" (often read out loud as "goes to").

5. The Built-in Delegates

In all our previous examples, we had to declare public delegate bool ArticleFilter(Article article); at the top of our class.

Declaring a custom delegate type every time you want to use a lambda is extremely annoying. To solve this, Microsoft added three generic delegates directly into C# so you never have to declare your own again: Action, Func, and Predicate.

Action, Func, and Predicate Explained

1. Action<T> (Always returns void)

Use Action when your lambda performs a task but doesn't need to return an answer (like printing to the console).

// Action<Article> means: "A method that takes an Article and returns void."
Action<Article> printArticle = article => Console.WriteLine(article.Title);

2. Func<TInput, TOutput> (Always returns a value)

Use Func when your lambda needs to calculate or return a value. The LAST generic parameter is ALWAYS the return type.

// Func<Article, string> means: "Takes an Article, returns a string."
Func<Article, string> getTitle = article => article.Title.ToUpper();

// Func<User, Article, bool> means: "Takes a User and Article, returns a bool."
Func<User, Article, bool> canEdit = (user, article) => user.Id == article.AuthorId;

3. Predicate<T> (Always returns a bool)

Predicate<T> and Func<T, bool> have the exact same shape (they both take an input and return a bool). However, Predicate<T> is a special delegate specifically designed for True/False filtering tests (like checking if an article is published).

// Predicate<Article> means: "Takes an Article, tests it, and returns true/false."
Predicate<Article> isPublished = article => article.IsPublished == true;

Complete Code Example (Built-ins)

Here is a complete program showing how all three built-in delegates replace the need for custom delegates.

C# - Using Action, Func, and Predicate
using System;

namespace KnowledgeBase 
{
    public class Article 
    { 
        public string Title { get; set; } 
        public int ViewCount { get; set; }
    }

    class Program 
    {
        static void Main() 
        {
            Article myArticle = new Article { Title = "Understanding Delegates", ViewCount = 500 };

            // 1. PREDICATE (Takes Article, returns bool for filtering)
            Predicate<Article> isPopular = article => article.ViewCount > 100;
            Console.WriteLine($"Is Popular? {isPopular(myArticle)}");

            // 2. FUNC (Takes Article, returns a string)
            Func<Article, string> formatTitle = article => $"[{article.Title.ToUpper()}]";
            Console.WriteLine($"Formatted: {formatTitle(myArticle)}");

            // 3. ACTION (Takes Article, returns void)
            Action<Article> printDetails = article => Console.WriteLine($"Article '{article.Title}' has {article.ViewCount} views.");
            printDetails(myArticle);
        }
    }
}
Console Output:
Is Popular? True
Formatted: [UNDERSTANDING DELEGATES]
Article 'Understanding Delegates' has 500 views.
Advanced Note: Target Typing

You cannot write var myLogic = article => article.Title; because the compiler doesn't know what delegate type you want (Func? Expression Tree?).

The compiler requires a Target Type (like Func<Article, string>). Once you provide the target type, the compiler instantly knows that article is an Article without you having to explicitly declare it!

6. Built-in List<T> Methods

Because passing logic as a parameter is so powerful, Microsoft built methods directly into List<T> that accept Predicate<T> and Action<T>.

C# - List<T> Lambda Methods
using System;
using System.Collections.Generic;

namespace KnowledgeBase 
{
    public class Article { public string Title { get; set; } public bool IsDraft { get; set; } }

    class Program 
    {
        static void Main() 
        {
            List<Article> articles = new List<Article> {
                new Article { Title = "C# 101", IsDraft = true },
                new Article { Title = "SQL basics", IsDraft = false },
                new Article { Title = "LINQ Guide", IsDraft = true }
            };

            // 1. FindAll (Requires a Predicate. Returns a NEW LIST of all matches)
            List<Article> allDrafts = articles.FindAll(article => article.IsDraft == true);

            // 2. Find (Requires a Predicate. Returns the FIRST matching item, or null)
            Article firstDraft = articles.Find(article => article.IsDraft == true);

            // 3. Exists (Requires a Predicate. Returns true if AT LEAST ONE item matches)
            bool hasDrafts = articles.Exists(article => article.IsDraft == true);

            // 4. RemoveAll (Requires a Predicate. Deletes all matching items, returns count removed)
            int removedCount = articles.RemoveAll(article => article.Title.Contains("SQL"));

            // 5. ForEach (Requires an Action. Executes it on every item)
            articles.ForEach(article => Console.WriteLine(article.Title));
        }
    }
}

Method Groups (Shortcut)

When you have an existing named method that exactly matches the delegate signature (e.g., takes an Article, returns void), you can pass the method name directly instead of writing a lambda. This is called a Method Group.

static void PrintArticle(Article a) { Console.WriteLine(a.Title); }

// Using a Lambda
articles.ForEach(article => PrintArticle(article));

// Using a Method Group (Cleaner!)
articles.ForEach(PrintArticle);

7. Variable Capture (Closures)

What it is:When a lambda expression uses a variable declared completely outside of the lambda.
Why it exists:Lambdas often need dynamic parameters (like search terms or IDs) from the surrounding method to function properly.
int targetAuthorId = 101;
      ↓
(declared outside lambda)
      ↓
(lambda reaches out and uses it)
      ↓
articles.FindAll(article => article.AuthorId == targetAuthorId);

The lambda captures the variable itself, rather than simply taking a one-time copy of its value. This is known as variable capture (or creating a closure).

Advanced Note: The "For Loop" Capture Trap Because the lambda captures the variable and not a snapshot of its value, if you capture a loop variable (like i in a for loop) inside a lambda, all lambdas will share that same exact variable. When they execute later, they will all see the final value of i!

8. When to use a Lambda vs Named Method

These are guidelines, not hard rules.

Prefer a lambda:When the logic is short; it is used locally; the meaning is obvious where it appears; it is convenient to pass behavior into another method.
Prefer a named method:When the logic is complex; it is reused across many files; it deserves a meaningful name; it needs independent unit testing; the lambda becomes difficult to read.

9. The LINQ Connection (Preview)

Up until now, we used List<T>.FindAll(). But FindAll only exists on Lists.

This is why LINQ (Language Integrated Query) exists. LINQ uses lambda expressions extensively to describe operations such as filtering, selecting, ordering, and grouping on Arrays, Databases, and more!

// A preview of LINQ (System.Linq) using the exact same lambda syntax!
var publishedArticles = articles.Where(article => article.IsPublished == true);

Do not worry about LINQ yet. Just understand that article => ... is the core building block of all advanced C# data querying.

Knowledge Base Lambda Demo

This complete, traditional Program.cs file demonstrates everything covered above.

C# - Program.cs
using System;
using System.Collections.Generic;

namespace KnowledgeBase {
    
    #region Enums
    /// <summary>Defines the lifecycle status of an article.</summary>
    public enum EnmArticleStatus { Draft, PendingReview, NeedsImprovement, Rejected, Published }
    
    /// <summary>Defines the security role of a user.</summary>
    public enum EnmRole { Author, Reviewer, Editor }
    #endregion

    #region Domain Classes
    public class User {
        public int Id { get; set; }
        public string Name { get; set; }
        public EnmRole Role { get; set; }
    }

    public class Article {
        public int Id { get; set; }
        public string Title { get; set; }
        public int AuthorId { get; set; }
        public EnmArticleStatus Status { get; set; }
        public int ViewCount { get; set; }
    }
    #endregion

    class Program {
        static void Main(string[] args) {
            
            List<Article> articles = new List<Article> {
                new Article { Id = 1, Title = "C# Basics", AuthorId = 101, Status = EnmArticleStatus.Published, ViewCount = 1500 },
                new Article { Id = 2, Title = "OOP Guide", AuthorId = 101, Status = EnmArticleStatus.Draft, ViewCount = 0 },
                new Article { Id = 3, Title = "Advanced SQL", AuthorId = 102, Status = EnmArticleStatus.PendingReview, ViewCount = 0 },
                new Article { Id = 4, Title = "APIs in C#", AuthorId = 103, Status = EnmArticleStatus.Published, ViewCount = 500 }
            };

            User currentEditor = new User { Id = 999, Name = "Alice", Role = EnmRole.Editor };

            Console.WriteLine("=== 1. FILTERING (Predicate) ===");
            // FindAll requires a Predicate<Article> (returns bool)
            List<Article> publishedArticles = articles.FindAll(article => article.Status == EnmArticleStatus.Published);
            Console.WriteLine($"Found {publishedArticles.Count} published articles.");

            Console.WriteLine("\n=== 2. FINDING SINGLE ITEM (Predicate) ===");
            // Find returns the first match or null
            Article sqlArticle = articles.Find(article => article.Title.Contains("SQL"));
            Console.WriteLine($"Found SQL Article ID: {sqlArticle?.Id}");

            Console.WriteLine("\n=== 3. CHECKING EXISTENCE (Predicate) ===");
            bool hasDrafts = articles.Exists(article => article.Status == EnmArticleStatus.Draft);
            Console.WriteLine($"System has drafts: {hasDrafts}");

            Console.WriteLine("\n=== 4. DISPLAYING (Action) ===");
            // ForEach requires an Action<Article> (returns void)
            publishedArticles.ForEach(article => Console.WriteLine($"- {article.Title} ({article.ViewCount} views)"));

            Console.WriteLine("\n=== 5. VARIABLE CAPTURE (Closure) ===");
            int searchAuthorId = 101; 
            // The lambda captures searchAuthorId
            List<Article> author101Articles = articles.FindAll(article => article.AuthorId == searchAuthorId);
            Console.WriteLine($"Author 101 has {author101Articles.Count} articles.");

            Console.WriteLine("\n=== 6. CALCULATION (Func) ===");
            // Func<Article, double> takes an Article and returns a double
            Func<Article, double> calculateAdRevenue = article => article.ViewCount * 0.05;
            Console.WriteLine($"Revenue for '{articles[0].Title}': ${calculateAdRevenue(articles[0])}");
            
            Console.ReadLine();
        }
    }
}

Find the Error

1. Func<Article, string> getTitle = article => Console.WriteLine(article.Title);
Error: Func expects a return value of type string. Console.WriteLine returns void. This should be an Action<Article>.
2. Predicate<Article> isDone = article => { article.Status == EnmArticleStatus.Published };
Error: If you use curly braces {} (Statement Lambda), you MUST use the return keyword. Correct: { return article.Status == EnmArticleStatus.Published; }
3. Action<User, Article> log = user, article => Console.WriteLine(user.Name);
Error: When you have multiple parameters, you MUST wrap them in parentheses: (user, article) => ...

Interview & Revision Questions

1. What is the fundamental difference between an Action and a Func?
Action ALWAYS returns void (it performs a task). Func ALWAYS returns a value (it calculates or retrieves something).
2. What is a Predicate, and how does it relate to Func?
They have the same basic input/output shape, but they are different delegate types. Predicate<T> is specifically designed to represent a true/false test, whereas Func<T, bool> is a general function returning a boolean.
3. Explain what a "Closure" or "Variable Capture" is in the context of Lambdas.
It is when a lambda expression uses a variable that was declared outside of the lambda. The lambda captures the variable itself, so it can still use it even if it executes later.
4. Why was the lambda operator (=>) introduced to C#?
To provide a concise, readable syntax for creating inline logic, reducing the boilerplate of C# 2.0 anonymous delegates.
5. What does the last generic parameter in a Func<> declaration always represent?
The return type of the method. For example, in Func<int, string, bool>, it takes an int and a string, and returns a bool.
6. If a lambda contains an if-statement, can you use Expression-body syntax (without curly braces)?
No. You can only use a ternary operator (condition ? true : false) without curly braces. If you write an actual if keyword, you must use a Statement body with {} and return.
7. What happens if List.Find() cannot find any item matching the lambda condition?
It returns the default value for the type. For reference types (like classes), it returns null. For value types (like structs), it returns the zero-initialized struct.
8. In C#, is a lambda expression executed immediately when it is defined?
No. A lambda expression describes logic. It only executes when the delegate variable it was assigned to is invoked.
