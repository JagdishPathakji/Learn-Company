C# LINQ (Language Integrated Query)

Difficulty: Advanced | Category: C# Data Processing & Functional Querying

Source Material Note

This chapter contains the complete notes, architectural diagrams, pitfall analyses, and runnable code directly imported from the training curriculum repository (Desktop/Training/C#/LINQ), covering in-memory collections, lazy evaluation semantics, and DataTable interop.

Lesson 1 — Why LINQ?

Before learning LINQ, let us understand the exact problem it solves in software engineering.

Suppose our KnowledgeBase application has a collection of articles:

C# - Domain Models
List<Article> articles;

// Each Article contains:
// - ArticleId
// - Title
// - StatusId
// - AuthorId

Now suppose we want: "Give me all published articles".

Without LINQ, we write a manual imperative loop:

C# - Imperative Filtering Loop
List<Article> published = new List<Article>();

foreach (Article article in articles) 
{
    if (article.StatusId == 5) 
    {
        published.Add(article);
    }
}

This works. So the fundamental question is: "WHY DO WE NEED LINQ?"

Because real-world applications constantly need to perform repetitive operations on data:

  1. Find all published articles
  2. Find articles written by a particular author
  3. Find articles whose title contains "SQL"
  4. Sort articles by title
  5. Find the first article with status "published"
  6. Count matching articles

Without LINQ, we constantly write boilerplate loops. In each problem, the exact condition changes, but the core process is identical:

COLLECTION ──► Examine each element ──► Apply some logic ──► Produce a result

LINQ gives us a unified, declarative standard to express these operations:

  • LINQ = Language Integrated Query
  • It is a first-class set of C#/.NET features used to query and manipulate data.
  • It provides a concise, readable syntax to query data instead of writing raw loops every single time.
C# - Declarative Query
var published = articles.Where(a => a.StatusId == 5);

The primary advantage of LINQ is composability: it provides reusable operations for common data-processing tasks and lets you chain them sequentially:

C# - Composed LINQ Pipeline
var titles = articles
    .Where(a => a.StatusId == 5)
    .Where(a => a.AuthorId == 101)
    .OrderBy(a => a.Title)
    .Select(a => a.Title);

Each operation produces something that can be passed directly to the next operation. That ability to combine operations is the cornerstone of LINQ.

SQL vs LINQ

SQL is primarily used to query databases over a network. LINQ is part of C#/.NET and works with many kinds of data: in-memory collections, arrays, XML, JSON, DataTables, and remote databases (via Entity Framework / IQueryable).

Lesson 2 — IEnumerable<T> and the LINQ Hierarchy

In Lesson 1 we saw:

articles.Where(a => a.StatusId == 5);

The question is: How does .Where() work on List<Article>?

List<T> does not define a method called Where(). So where does it come from?

The answer: LINQ methods are Extension Methods defined on IEnumerable<T>. They live in the static class System.Linq.Enumerable and target this IEnumerable<TSource>.

Because List<Article> implements IEnumerable<Article>, it automatically gains access to Where(), Select(), OrderBy(), Count(), and every other LINQ method. This is why understanding IEnumerable<T> is the real foundation of LINQ.

The .NET Collection Hierarchy

IEnumerable (non-generic, .NET 1.0 style, works with 'object') │ IEnumerable<T> (generic version, type-safe, this is what LINQ targets) │ ICollection<T> (adds Count, Add, Remove, Contains) │ IList<T> (adds indexer: list[i], Insert, RemoveAt) │ List<T> (the concrete class you actually instantiate)

When you declare:

List<Article> articles;

articles is-a IList<Article>, which is-a ICollection<Article>, which is-a IEnumerable<Article>.

Because of this inheritance chain, every LINQ method that expects an IEnumerable<T> happily accepts a List<T>, an Article[] array, a HashSet<Article>, a Dictionary<TKey, TValue>.Values, or literally anything that can be iterated element-by-element.

IEnumerable<T> vs IQueryable<T>
  • IEnumerable<T> ("LINQ to Objects"): Operates on in-memory data (List, Array, DataTable rows after AsEnumerable). Executes compiled C# code in memory, step-by-step.
  • IQueryable<T> ("LINQ to SQL / Entity Framework"): Holds an Expression Tree. Instead of running C# loops, EF passes the expression tree to a provider that translates your LINQ into pure SQL queries executed directly by the database server.

Lesson 3 — Filtering Deep Dive: Where()

Method Signatures

Where() has two overloads in System.Linq.Enumerable:

C# - Overload 1: Standard Predicate
public static IEnumerable<TSource> Where<TSource>(
    this IEnumerable<TSource> source, 
    Func<TSource, bool> predicate)
C# - Overload 2: Indexed Predicate
public static IEnumerable<TSource> Where<TSource>(
    this IEnumerable<TSource> source, 
    Func<TSource, int, bool> predicate)

// Example: filter by position in sequence (0-based)
List<Article> everyOther = articles
    .Where((a, index) => index % 2 == 0)
    .ToList();
Crucial Execution Detail

Where() does not create a new List<Article> by itself. It returns an IEnumerable<Article>. Calling .ToList() at the end is what actually forces it to execute the loop and collect results into a real List<Article>.

Filtering with Null Checks

A classic production bug is forgetting that a property might be null, crashing with a NullReferenceException.

WRONG (Crashes at runtime if Summary is null): 
var withSql = articles
    .Where(a => a.Summary.Contains("SQL"))
    .ToList();
CORRECT - Guard the null check first:
// Approach A: Explicit null guard
var withSql = articles
    .Where(a => a.Summary != null && a.Summary.Contains("SQL"))
    .ToList();

// Approach B: Null-conditional operator
var withSql = articles
    .Where(a => a.Summary?.Contains("SQL") == true)
    .ToList();

Common Rules of Where()

  1. Where() does not modify the original collection.
  2. Where() executes lazily. If you define var q = articles.Where(...); and then call articles.Clear();, executing q.ToList() yields 0 elements because it re-evaluates the recipe against the cleared source.

Lesson 4 — Projection: Select() & SelectMany()

Select() keeps every element, but transforms each one into something else. This transformation is called Projection.

Where() ──► "Which items do I want to keep?" (filters rows) Select() ──► "What shape do I want each item in?" (shapes columns/types)

The Select() Signature

C# - Select Signature
public static IEnumerable<TResult> Select<TSource, TResult>(
    this IEnumerable<TSource> source,
    Func<TSource, TResult> selector)

Notice there are two generic type parameters: TSource and TResult. Where() only has TSource because filtering never changes the underlying type. Select() can take in Article and output string, int, an anonymous type, or a DTO class.

Four Common Select() Variations

Variation 1 — Projecting to a Single Property

C# - Single Property
List<string> titlesOnly = articles
    .Select(a => a.Title)
    .ToList();

Variation 2 — Projecting into an Anonymous Type

C# - Anonymous Type
var titleAndAuthor = articles
    .Select(a => new { a.Title, a.AuthorId })
    .ToList();

Limitation: Anonymous types cannot be returned as public method return types; they are intended for local, throwaway operations.

Variation 3 — Projecting into a DTO (Data Transfer Object)

C# - DTO Projection
public class ArticleDto
{
    public string Title { get; set; }
    public string AuthorName { get; set; }
}

List<ArticleDto> dtos = articles
    .Select(a => new ArticleDto
    {
        Title = a.Title,
        AuthorName = "Author #" + a.AuthorId
    })
    .ToList();

Variation 4 — Indexed Select()

C# - Indexed Select
var numbered = articles
    .Select((a, index) => $"{index + 1}. {a.Title}")
    .ToList();

SelectMany() — Flattening Nested Collections

Select() is 1-to-1: each input element produces exactly one output element. If an element contains a nested collection, Select() produces a list of lists (List<List<string>>).

SelectMany() is 1-to-Many, Flattened: each input element produces a collection, and all those inner collections are concatenated into one flat sequence.

C# - Select vs SelectMany Comparison
// Given Article with List<string> Tags:
// articles[0].Tags = ["sql", "database"]
// articles[1].Tags = ["linq", "csharp"]

// WRONG TOOL (Select): Produces List<List<string>>
var wrong = articles.Select(a => a.Tags).ToList();

// RIGHT TOOL (SelectMany): Produces flat List<string>
// Result: ["sql", "database", "linq", "csharp"]
var allTags = articles
    .SelectMany(a => a.Tags)
    .ToList();

Comprehensive Code: Where(), Select(), and SelectMany()

C# - Real World Demonstrations
// 1) Multiple conditions combined with &&
var publishedByAuthor101 = articles
    .Where(a => a.StatusId == 5 && a.AuthorId == 101)
    .Select(a => a.Title)
    .ToList();

// 2) Chained Where calls (identical execution semantics to &&)
var chained = articles
    .Where(a => a.StatusId == 5)
    .Where(a => a.AuthorId == 101)
    .Select(a => a.Title)
    .ToList();

// 3) Optional / Conditional Filters (Search Screen Pattern)
int? statusId = 5;
int? authorId = 101;
string titleContains = null;

IEnumerable<Article> query = articles;

if (statusId.HasValue)
    query = query.Where(a => a.StatusId == statusId.Value);

if (authorId.HasValue)
    query = query.Where(a => a.AuthorId == authorId.Value);

if (!string.IsNullOrWhiteSpace(titleContains))
    query = query.Where(a => a.Title.Contains(titleContains, StringComparison.OrdinalIgnoreCase));

var searchResults = query.Select(a => a.Title).ToList();

Lessons 5–13 — Standard Operators Reference

The following examples demonstrate the full operator suite using our standard domain dataset (Article and Author).

Lesson 5 — Ordering: OrderBy(), OrderByDescending(), ThenBy()

C# - Sorting Variations
// 1) Ascending sort
var byTitleAsc = articles.OrderBy(a => a.Title).ToList();

// 2) Descending sort
var byDateDesc = articles.OrderByDescending(a => a.CreatedDate).ToList();

// 3) Secondary sorting: ThenBy() / ThenByDescending()
var byAuthorThenTitle = articles
    .OrderBy(a => a.AuthorId)
    .ThenBy(a => a.Title)
    .ToList();
CRITICAL MISTAKE: Never chain OrderBy().OrderBy()

Writing articles.OrderBy(a => a.AuthorId).OrderBy(a => a.Title) is incorrect. The second OrderBy() call completely overwrites the first sort instead of refining it. Always use ThenBy() or ThenByDescending() for secondary sort keys.

Lesson 6 — Paging & Partitioning: Skip(), Take(), SkipWhile(), TakeWhile()

C# - Pagination Pattern
// Standard Web API Pagination: Page 2 with PageSize 2
int pageNumber = 2;   // 1-based page index
int pageSize = 2;

var page2 = articles
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize)
    .Select(a => a.Title)
    .ToList();

// TakeWhile: takes elements while condition holds, stops at first failure
var takeWhilePublished = articles.TakeWhile(a => a.StatusId == 5).ToList();

// SkipWhile: skips elements while condition holds, then takes all remaining
var skipWhilePublished = articles.SkipWhile(a => a.StatusId == 5).ToList();

Lesson 7 — Element Operators: First, Single, Last

Method Matches Found = 0 Matches Found = 1 Matches Found > 1 Recommended Use
First() Throws InvalidOperationException Returns element Returns first element When at least one match MUST exist
FirstOrDefault() Returns null / default Returns element Returns first element Safest general choice when match is optional
Single() Throws InvalidOperationException Returns element Throws InvalidOperationException Lookup by unique key (enforces uniqueness)
SingleOrDefault() Returns null / default Returns element Throws InvalidOperationException Unique key lookup where record may not exist
C# - Element Operators Code
// FirstOrDefault: safe fallback
var firstDraft = articles.FirstOrDefault(a => a.StatusId == 99); // returns null

// Single: enforces exactly 1 match
var singleAuthor103 = articles.Single(a => a.AuthorId == 103);

Lesson 8 — Quantifiers: Any(), All(), Contains()

C# - Quantifiers
// 1) Does collection contain ANY elements?
bool hasArticles = articles.Any();

// 2) Does at least one element match?
bool hasDrafts = articles.Any(a => a.StatusId == 1);

// 3) Do ALL elements match?
bool allPublished = articles.All(a => a.StatusId == 5);

// 4) Contains() on simple value sequence
var allTags = articles.SelectMany(a => a.Tags).ToList();
bool hasSql = allTags.Contains("sql");
Gotcha: Vacuous Truth in All()

Calling All() on an empty sequence returns true! E.g.: articles.Where(a => a.StatusId == 999).All(a => a.StatusId == 5) evaluates to true because there are no elements violating the condition.

Lesson 9 & 10 — Aggregation & Custom Fold: Count, Sum, Average, Min, Max, Aggregate

C# - Aggregation Code
int totalArticles = articles.Count();
int publishedCount = articles.Count(a => a.StatusId == 5);
int totalTags = articles.Sum(a => a.Tags.Count);
double avgTags = articles.Average(a => a.Tags.Count);

// .NET 6+ MinBy / MaxBy (returns the actual object, not just scalar key)
Article oldestArticle = articles.MinBy(a => a.CreatedDate);
Article newestArticle = articles.MaxBy(a => a.CreatedDate);

// Aggregate() - custom accumulator (Fold / Reduce)
// 1) Concatenate titles with comma
string concatenated = articles
    .Select(a => a.Title)
    .Aggregate((acc, cur) => acc + ", " + cur);

// 2) Aggregate with seed value (0) and result selector
string summary = articles.Aggregate(
    0,
    (acc, a) => acc + a.Tags.Count,
    total => $"Total tags across articles: {total}");

Lesson 11 — Grouping: GroupBy()

C# - GroupBy Examples
// 1) Basic GroupBy returns IEnumerable<IGrouping<TKey, TElement>>
var byAuthor = articles.GroupBy(a => a.AuthorId);

// 2) GroupBy + Select into summary objects
var authorSummary = articles
    .GroupBy(a => a.AuthorId)
    .Select(g => new
    {
        AuthorId = g.Key,
        ArticleCount = g.Count(),
        Titles = g.Select(a => a.Title).ToList()
    })
    .ToList();

// 3) Group by composite key
var byStatusAndAuthor = articles.GroupBy(a => new { a.StatusId, a.AuthorId });

// 4) Ordering groups by aggregate count
var orderedGroups = articles
    .GroupBy(a => a.AuthorId)
    .OrderByDescending(g => g.Count())
    .ToList();

Lesson 12 — Set Operations: Distinct, Union, Intersect, Except

C# - Set Operations
List<int> teamA = new List<int> { 101, 102, 103 };
List<int> teamB = new List<int> { 102, 103, 104 };

// Distinct: removes duplicate values
var uniqueTags = articles.SelectMany(a => a.Tags).Distinct().ToList();

// Union: combines sets, eliminating duplicates (Mathematical OR)
var allTeamIds = teamA.Union(teamB).ToList(); // [101, 102, 103, 104]

// Intersect: only elements present in BOTH (Mathematical AND)
var commonIds = teamA.Intersect(teamB).ToList(); // [102, 103]

// Except: elements in first set NOT in second (Set Difference)
var onlyInA = teamA.Except(teamB).ToList(); // [101]

Lesson 13 — Relational Joins: Join, GroupJoin, Left Outer Join

C# - Joins Code
// 1) Inner Join: only matches where key exists on BOTH sides
var innerJoin = articles.Join(
    authors,
    article => article.AuthorId,
    author => author.AuthorId,
    (article, author) => new { article.Title, author.Name }
).ToList();

// 2) GroupJoin (Hierarchical / Left Join): keeps ALL authors, pairing each with their articles
var groupJoin = authors.GroupJoin(
    articles,
    author => author.AuthorId,
    article => article.AuthorId,
    (author, matchedArticles) => new { author.Name, Articles = matchedArticles.ToList() }
).ToList();

// 3) True Flattened Left Outer Join: GroupJoin + SelectMany + DefaultIfEmpty
var leftJoinFlattened = authors
    .GroupJoin(
        articles,
        author => author.AuthorId,
        article => article.AuthorId,
        (author, matchedArticles) => new { author, matchedArticles })
    .SelectMany(
        x => x.matchedArticles.DefaultIfEmpty(),
        (x, article) => new
        {
            AuthorName = x.author.Name,
            ArticleTitle = article == null ? "(no articles)" : article.Title
        })
    .ToList();

Deferred vs Immediate Execution

When you write:

var query = articles.Where(a => a.StatusId == 5);

At this line, NOTHING is executed. query is not a list or a result set. It is a stored PLAN: "when someone actually asks for values, loop through articles, and yield items where StatusId == 5."

The plan only executes when an operation forces enumeration:

  • A foreach loop
  • Conversion methods: .ToList(), .ToArray(), .ToDictionary(), .ToHashSet()
  • Scalar aggregators: .Count(), .Sum(), .Average(), .Min(), .Max()
  • Element pickers: .First(), .FirstOrDefault(), .Single(), .Any(), .All()

Categorization Table

Execution Type Return Type Methods
LAZY (Deferred)
Builds execution recipe; runs nothing immediately		 IEnumerable<T> / IOrderedEnumerable<T> Where, Select, SelectMany, OrderBy, ThenBy, Skip, Take, SkipWhile, TakeWhile, Distinct, GroupBy, Join, GroupJoin, Union, Intersect, Except
IMMEDIATE
Executes loop right away to produce concrete data		 Concrete collection (List<T>, T[]) or scalar (int, bool, T) ToList, ToArray, ToDictionary, ToHashSet, Count, Sum, Average, Min, Max, First, FirstOrDefault, Single, SingleOrDefault, Last, LastOrDefault, Any, All, Contains, Aggregate

Four Real-World LINQ Pitfalls (With Code Proofs)

Pitfall 1 — Source Changes Before Enumeration

Because lazy queries store a reference rather than a snapshot, mutating the source before materializing includes the modified data.

C# - Pitfall 1 Code Proof
List<Article> articles = new List<Article>
{
    new Article { ArticleId = 1, Title = "Intro to SQL", StatusId = 5 },
    new Article { ArticleId = 2, Title = "Draft Notes",  StatusId = 1 }
};

var query = articles.Where(a => a.StatusId == 5); // Unfired recipe

// Mutate source collection AFTER building query
articles.Add(new Article { ArticleId = 3, Title = "New Article", StatusId = 5 });

var result = query.ToList(); // Runs NOW: Includes "New Article"!

// FIX: If you need an immutable snapshot at definition time, call .ToList() immediately:
var snapshot = articles.Where(a => a.StatusId == 5).ToList();

Pitfall 2 — Multiple Enumeration (The #1 LINQ Bug)

Executing multiple operations against the same lazy IEnumerable<T> re-runs the entire pipeline from scratch on every call.

WRONG (Evaluates predicate 2x times per item): 
int callCount = 0;
IEnumerable<Article> query = articles.Where(a =>
{
    callCount++; // Side-effect to prove re-execution
    return a.StatusId == 5;
});

int count = query.Count();           // Pass 1: checks all 3 items (callCount = 3)
List<Article> list = query.ToList(); // Pass 2: checks all 3 items AGAIN (callCount = 6!)
THE FIX: Materialize once with .ToList()
List<Article> materialized = articles.Where(a => a.StatusId == 5).ToList(); // Runs ONCE

int countFromList = materialized.Count; // O(1) property read, zero loop passes
// Reuse 'materialized' everywhere else

Pitfall 3 — Accidentally Re-running Expensive Logic in Loops

Iterating over an unmaterialized IEnumerable<T> in multiple foreach loops repeats heavy database/CPU calculations twice. Always materialize once into a List<T> before multiple loops.

Pitfall 4 — Closure Trap (Captured Variables Change Before Enumeration)

Lambdas capture the variable reference, not the write-time value.

C# - Closure Trap Proof & Fix
int minStatus = 5;
var query = articles.Where(a => a.StatusId >= minStatus);

minStatus = 10; // Variable mutated BEFORE enumeration!

var result = query.ToList(); // Evaluates with minStatus = 10, NOT 5!

// ---- THE FIX: Freeze value into a local snapshot variable ----
int minStatusFixed = 5;
int frozenValue = minStatusFixed; // Snapshot captured here
var fixedQuery = articles.Where(a => a.StatusId >= frozenValue);

minStatusFixed = 10; // Does not affect fixedQuery! Result uses 5.

Good Use of Laziness — Short-Circuiting

Lazy evaluation allows LINQ to stop early the moment an answer is found, avoiding processing the rest of the list.

C# - Short-Circuiting Proof
int itemsChecked = 0;
var firstMatch = articles.Where(a =>
{
    itemsChecked++;
    return a.StatusId == 5;
}).First(); // Stops immediately when article #1 matches!

// itemsChecked will be 1, NOT the total list count!

LINQ to DataTable Deep Dive

Why DataTable Needs Special Treatment

DataTable.Rows returns a DataRowCollection, which implements the old .NET 1.0 non-generic IEnumerable. Because LINQ methods are extension methods on IEnumerable<T>, calling LINQ directly fails:

dataTable.Rows.Where(r => ...); // COMPILE ERROR: 'Where' not found!

To enable LINQ, .NET provides an extension method inside System.Data.DataSetExtensions:

using System.Data;

IEnumerable<DataRow> rows = dataTable.AsEnumerable(); // Unlocks ALL LINQ methods!

Reading Values & Handling DBNull with Field<T>()

Standard raw indexing ((string)row["Title"]) returns untyped object and crashes on nulls. Always use row.Field<T>("ColumnName"):

Data Type Field<T> Syntax Behavior on DBNull.Value
Reference Types (e.g. string) row.Field<string>("Summary") Returns C# null cleanly without crashing.
Non-Nullable Value Types (e.g. int) row.Field<int>("StatusId") THROWS exception if cell contains DBNull! (int cannot hold null).
Nullable Value Types (e.g. int?) row.Field<int?>("StatusId") Safely returns null (HasValue == false).
Golden Rule for DataTable Columns

If a value-type column can ever contain nulls in the database, always read it as nullable: row.Field<int?>("Col") or row.Field<DateTime?>("Col").

Recommended Pattern: Projecting DataRow into a Typed Class

Avoid scattering row.Field<T>() throughout your application. Project DataTable rows into typed DTOs/models once at the data-access boundary:

C# - DataRow to Typed Object Projection
List<Article> articles = dataTable.AsEnumerable()
    .Select(row => new Article
    {
        ArticleId = row.Field<int>("ArticleId"),
        Title     = row.Field<string>("Title"),
        StatusId  = row.Field<int>("StatusId"),
        AuthorId  = row.Field<int>("AuthorId")
    })
    .ToList();

// From this point onward, work with clean, type-safe List<Article> LINQ!

Converting Back to DataTable: CopyToDataTable() & The Empty Bug

When you need to export LINQ results back to legacy controls or tools, use CopyToDataTable().

DANGER: CopyToDataTable() Throws on Empty Sequences

If zero rows match your filter, CopyToDataTable() throws InvalidOperationException because an empty sequence provides no row schema to construct the table.

C# - The Safe CopyToDataTable Pattern
var filteredRows = dataTable.AsEnumerable().Where(row => row.Field<int>("StatusId") == 5);

// Guard with Any() and use Clone() as safe empty fallback:
DataTable resultTable = filteredRows.Any()
    ? filteredRows.CopyToDataTable()
    : dataTable.Clone(); // Clone() copies schema with zero rows -- 100% crash proof!

Four Common Mistakes with DataTable + LINQ

  1. Forgetting AsEnumerable(): dataTable.Rows.Where(...) fails to compile.
  2. Using Field<int>() on nullable columns: Throws runtime exception when encountering DBNull. Use Field<int?>().
  3. Unguarded CopyToDataTable(): Crashes on 0 matching rows. Guard with Any() ? ... : dataTable.Clone().
  4. Raw type casting ((string)row["Title"]): Fragile, untyped, and fails to handle DBNull safely. Always prefer Field<T>().

Complete Runnable Program: Datatable.cs

C# - Datatable.cs Complete Implementation
using System;
using System.Data;
using System.Linq;
using System.Collections.Generic;

public class Article
{
    public int ArticleId { get; set; }
    public string Title { get; set; }
    public int StatusId { get; set; }
    public int AuthorId { get; set; }
}

public class Program
{
    public static void Main()
    {
        DataTable dataTable = BuildSampleDataTable();

        // 1. AsEnumerable() basics
        IEnumerable<DataRow> rows = dataTable.AsEnumerable();
        Console.WriteLine($"Total rows: {rows.Count()}");

        // 2. Field<T> and DBNull handling
        foreach (DataRow row in dataTable.AsEnumerable())
        {
            int articleId = row.Field<int>("ArticleId");
            string summary = row.Field<string>("Summary") ?? "(no summary)";
            Console.WriteLine($"ArticleId {articleId}: {summary}");
        }

        // 3. Where & Select directly on DataRows
        var publishedTitles = dataTable.AsEnumerable()
            .Where(row => row.Field<int>("StatusId") == 5)
            .Select(row => row.Field<string>("Title"))
            .ToList();

        // 4. Project DataRows into typed objects (Recommended pattern)
        List<Article> articles = dataTable.AsEnumerable()
            .Select(row => new Article
            {
                ArticleId = row.Field<int>("ArticleId"),
                Title     = row.Field<string>("Title"),
                StatusId  = row.Field<int>("StatusId"),
                AuthorId  = row.Field<int>("AuthorId")
            })
            .ToList();

        // 5. OrderBy & GroupBy on DataRows
        var grouped = dataTable.AsEnumerable()
            .GroupBy(row => row.Field<int>("AuthorId"))
            .Select(g => new { AuthorId = g.Key, Count = g.Count() })
            .ToList();

        // 6. Safe CopyToDataTable with Clone() fallback
        var matchRows = dataTable.AsEnumerable().Where(r => r.Field<int>("StatusId") == 5);
        DataTable safeTable = matchRows.Any() ? matchRows.CopyToDataTable() : dataTable.Clone();
    }

    static DataTable BuildSampleDataTable()
    {
        DataTable table = new DataTable("Articles");
        table.Columns.Add("ArticleId", typeof(int));
        table.Columns.Add("Title", typeof(string));
        table.Columns.Add("StatusId", typeof(int));
        table.Columns.Add("AuthorId", typeof(int));
        table.Columns.Add("Summary", typeof(string)); // Contains DBNull for some rows

        table.Rows.Add(1, "Intro to SQL", 5, 101, "Learn SQL basics");
        table.Rows.Add(2, "Advanced LINQ", 5, 102, DBNull.Value);
        table.Rows.Add(3, "Draft Notes", 1, 101, "Not ready yet");
        table.Rows.Add(4, "SQL Performance", 5, 101, "Tuning SQL queries");
        table.Rows.Add(5, "C# Basics", 5, 103, DBNull.Value);

        return table;
    }
}
