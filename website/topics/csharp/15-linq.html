LINQ (Language Integrated Query)

Difficulty: Intermediate | Category: C# Data Processing

The Power of "What", Not "How"

You know Lambda Expressions (how to pass logic) and Extension Methods (how to call it elegantly). Now, you will combine them to master LINQ. By the end of this module, you will be able to slice, filter, group, and query massive amounts of data with readable code.

1. The Problem LINQ Solves

Imagine we have a List<Article> and we want to find all published articles.

Before LINQ (The "How" approach)

We have to manually write the looping and filtering logic, telling the computer how to do the work step-by-step.

List<Article> publishedArticles = new List<Article>();
foreach (Article article in articles)
{
    if (article.Status == EnmArticleStatus.Published)
    {
        publishedArticles.Add(article);
    }
}

With LINQ (The "What" approach)

LINQ allows us to describe what data we want, instead of manually writing the looping and filtering logic every time.

List<Article> publishedArticles = articles
    .Where(article => article.Status == EnmArticleStatus.Published)
    .ToList();

2. What Is LINQ?

Language Integrated Query provides a consistent way to work with data.

  • Language Integrated: The query syntax is built directly into C#. You get autocomplete, compile-time checking, and refactoring support.
  • Query: A request for data (filtering, transforming, sorting).

There are two primary families of LINQ:

Enumerable ↓ IEnumerable<T> ↓ LINQ to Objects (executes in-memory over Lists, Arrays, etc.) Queryable ↓ IQueryable<T> ↓ LINQ providers such as EF Core (executes queries on a database)

Both families share the same mental model: Data → Operators → Result.

3. The Foundation: LINQ, Lambdas, and Extension Methods

Look at the statement below. It relies entirely on the two previous modules you learned.

articles ↓ extension method ↓ Where(...) ↓ lambda expression ↓ condition applied to articles

4. Where() — Filtering

IEnumerable<Article> (Input) ↓ Where(article => article.Status == EnmArticleStatus.Published) ↓ IEnumerable<Article> (Output)

What it does: Filters a sequence based on a true/false condition.
The Lambda: Accepts a Func<TSource, bool>. Because `Func` represents a method that takes a T and returns a boolean, a lambda like article => article.Status == EnmArticleStatus.Published perfectly matches this signature.

// Single condition
var drafts = articles.Where(a => a.Status == EnmArticleStatus.Draft);

// Multiple conditions using && and ||
var popularPublished = articles.Where(a => 
    a.Status == EnmArticleStatus.Published && 
    a.ViewCount > 1000);

5. Select() — Projection

Projection is one of the most important LINQ concepts. It means transforming the shape of the data.

IEnumerable<Article> (Input) ↓ Select(article => article.Title) ↓ IEnumerable<string> (Output)

What it does: Decides WHAT each item becomes. Notice the output type changes!
The Lambda: Accepts a Func<TSource, TResult>.

// Extracting a single property (Article -> string)
var titles = articles.Select(a => a.Title);

// Projecting into a new Anonymous Object (Article -> AnonymousType)
var summaries = articles.Select(a => new {
    a.Id,
    a.Title,
    a.ViewCount
});
Crucial Distinction:
Where() decides WHICH items remain.
Select() decides WHAT each item becomes.

6. Filtering + Projection (Chaining)

Because these methods operate on and return sequences, you can chain them.

var publishedTitles = articles
    .Where(article => article.Status == EnmArticleStatus.Published)
    .Select(article => article.Title)
    .ToList();
All Articles (List<Article>) ↓ Where Published Articles (IEnumerable<Article>) ↓ Select Article Titles (IEnumerable<string>) ↓ ToList List<string>

7. Sorting

// Primary Sort
var sorted = articles.OrderBy(a => a.Title);
var sortedDesc = articles.OrderByDescending(a => a.ViewCount);

// Secondary Sort (Use ThenBy)
var multiSorted = articles
    .OrderBy(a => a.Status)
    .ThenBy(a => a.Title);
OrderBy vs ThenBy If you want a secondary ordering, use ThenBy(). A second OrderBy() establishes another primary ordering rather than expressing a secondary sort, effectively overwriting your first sort.

8. Element Operators

These extract a specific item from a sequence. Methods ending in OrDefault (like FirstOrDefault(), SingleOrDefault(), and ElementAtOrDefault()) return the type's default value when no result exists. For reference types, this is normally null. For value types, it can be 0 or false. (Note: If nullable reference types are enabled, the compiler may flag this, and you must handle the possibility of a no-result scenario).

Method If Sequence is Empty / No Match If Multiple Matches Exist
First() Throws Exception Returns first item
FirstOrDefault() Returns default value (e.g., null for objects, 0 for ints) Returns first item
Single() Throws Exception Throws Exception
SingleOrDefault() Returns default value Throws Exception

9. Any() and All()

// True if AT LEAST ONE draft exists
bool hasDrafts = articles.Any(a => a.Status == EnmArticleStatus.Draft);

// True if EVERY article has views >= 0
bool allValid = articles.All(a => a.ViewCount >= 0);

Note: All() returns true on an empty sequence, while Any() returns false.

10. Aggregation

int totalArticles = articles.Count();
int totalViews = articles.Sum(a => a.ViewCount);
double avgViews = articles.Average(a => a.ViewCount);
int mostViews = articles.Max(a => a.ViewCount);
int leastViews = articles.Min(a => a.ViewCount);

Warning: Calling Average(), Min(), or Max() on an empty sequence of non-nullable value types will throw an InvalidOperationException. However, Sum() safely returns 0 on an empty sequence. If you expect empty sequences, consider projecting to nullable types (e.g., articles.Max(a => (int?)a.ViewCount)) which will safely return null instead of throwing.

11. Pagination & Partitioning

Skip(10) → Ignore first 10 items Take(10) → Take the next 10 items and stop
// Get Page 2 (assuming 10 items per page)
var page2 = articles
    .OrderBy(a => a.Title) // ALWAYS order before pagination!
    .Skip(10)
    .Take(10)
    .ToList();

// Partition conditionally
var upToFirstDraft = articles.TakeWhile(a => a.Status == EnmArticleStatus.Published);
var skipUntilDraft = articles.SkipWhile(a => a.Status == EnmArticleStatus.Published);

12. Sequence & Equality

// Contains: Checks if an item exists based on equality
bool hasId101 = authorIds.Contains(101);
// Note: Contains() can also accept an equality comparer when custom equality behavior is required.

// SequenceEqual: Checks if two sequences have the same elements in the exact same order
bool match = list1.SequenceEqual(list2);

13. GroupBy() and ToLookup()

GroupBy partitions your data into chunks based on a key (deferred). ToLookup does the same, but immediately materializes into a lookup structure.

Articles ↓ GroupBy(article => article.Status) ↓ Group 1 (Key: Draft) -> [Article1, Article4] Group 2 (Key: Published) -> [Article2, Article3]
// Common Pattern: Grouping and projecting into a summary
var articleCounts = articles
    .GroupBy(article => article.Status)
    .Select(group => new
    {
        Status = group.Key, // The property we grouped by
        Count = group.Count() // The group itself acts as an IEnumerable of articles
    })
    .ToList();

// ToDictionary vs ToLookup
// ToDictionary: Expects exactly ONE value per key. Duplicate keys throw an exception!
// ToLookup: Allows MULTIPLE values per key. Perfect for one-to-many lookups!

// If Author 1 has written 3 articles, this THROWS an Exception:
// var dict = articles.ToDictionary(a => a.AuthorId);

// This works perfectly, grouping all 3 articles under Author 1:
var articlesByAuthor = articles.ToLookup(a => a.AuthorId);
var bobArticles = articlesByAuthor[2]; // Fast retrieval of AuthorId 2's articles

14. Joining Data

LINQ can join two sequences together based on matching keys.

// Inner Join
var articleAuthors = articles.Join(
    users, // sequence to join
    article => article.AuthorId, // key from articles
    user => user.Id, // key from users
    (article, user) => new { article.Title, user.Name }); // projection

// GroupJoin (Grouped Matching / Left Join pattern)
// 1. GroupJoin (Grouped Matching)
// Produces each outer element together with a collection of matching inner elements.
var groupedMatches = users.GroupJoin(
    articles, user => user.Id, article => article.AuthorId,
    (user, userArticles) => new { User = user, Articles = userArticles }
);

// 2. Traditional Left Outer Join (GroupJoin + SelectMany + DefaultIfEmpty)
// To get a flat "SQL-style" left join, we flatten the grouped matches, providing a null article if the collection is empty.
var leftJoin = users.GroupJoin(
    articles, user => user.Id, article => article.AuthorId,
    (user, userArticles) => new { user, userArticles }
).SelectMany(
    x => x.userArticles.DefaultIfEmpty(), 
    (x, article) => new { x.user.Name, ArticleTitle = article?.Title ?? "No Articles" }
);

// 3. .NET 10 LeftJoin and RightJoin
// Modern .NET 10+ introduces dedicated operators to simplify this exact pattern natively:
// var modernLeftJoin = users.LeftJoin(articles, u => u.Id, a => a.AuthorId, (u, a) => new { u.Name, a?.Title });

15. SelectMany() — Flattening

If an Article contains a List<Tag>, Select gives you a list of lists. SelectMany flattens them into a single list.

Select → collection of collections SelectMany → flattened collection
// Gets all tags from all articles, flattened into one big list, removing duplicates
var allTags = articles
    .SelectMany(article => article.Tags)
    .Distinct()
    .ToList();

16. Combining Sequences & Sets

Distinct() uses equality comparison to determine whether two elements are equal. For custom objects, the result depends on the equality implementation being used (if value-based equality isn't defined, separate objects with identical property values are treated as different objects).

var noDuplicates = list1.Distinct();
var allCombined = list1.Concat(list2); // Keeps duplicates
var uniqueCombined = list1.Union(list2); // Removes duplicates
var commonOnly = list1.Intersect(list2);
var difference = list1.Except(list2);

// Modern .NET Key-based Set Operators
var unionByKey = list1.UnionBy(list2, a => a.Id);
var intersectByKey = list1.IntersectBy(list2.Select(a => a.Id), a => a.Id);
var exceptByKey = list1.ExceptBy(list2.Select(a => a.Id), a => a.Id);

var addedToEnd = articles.Append(newArticle);
var addedToStart = articles.Prepend(newArticle);

16b. Other Useful LINQ Operators

These supporting operators are highly useful for specific scenarios:

OfType<T>() and Cast<T>()
Filters (or casts) elements based on type.
var authors = allUsers.OfType<Author>(); // Safely ignores non-Authors
var articles = objects.Cast<Article>(); // Throws if cast fails
DefaultIfEmpty()
Returns the sequence, or a default-valued singleton collection if empty.
var safeList = articles.Where(a => a.Id == -1).DefaultIfEmpty(new Article { Title = "Empty" });
Reverse()
Inverts the order of the elements.
var backwards = articles.Reverse();
Zip()
Pairs up elements of two sequences based on index.
var paired = articles.Zip(users, (a, u) => $"{a.Title} by {u.Name}");
Aggregate()
Applies a rolling accumulator function over a sequence.
var csv = articles.Select(a => a.Title).Aggregate((current, next) => current + ", " + next);
LongCount()
Returns an Int64 count for massively large sequences (bypassing the 2 billion limit of int).
long total = dbContext.Articles.LongCount();
ElementAt() / ElementAtOrDefault()
Retrieves an element at a specific index. Throws / returns default if out of bounds.
var thirdArticle = articles.ElementAtOrDefault(2);
DistinctBy()
Removes duplicates based on a specific key selector (cleaner than custom comparers).
var uniqueAuthors = articles.DistinctBy(a => a.AuthorId);
MinBy() / MaxBy()
Returns the actual element that possesses the min/max value, not just the value itself.
Article mostViewed = articles.MaxBy(a => a.ViewCount);
Chunk()
Splits the elements into batches of a specific size.
IEnumerable<Article[]> batches = articles.Chunk(10);

17. Deferred Execution

Most LINQ operators (like Where, Select, OrderBy) do not execute immediately. They merely build a set of instructions. The query only actually runs when you iterate over it (e.g., in a foreach loop). Deferred execution does not mean "nothing happens internally", it means the operation waits until enumeration occurs.

Create query: var query = articles.Where(...) ↓ No enumeration yet ↓ Change source: articles.Add(new Article(...)) ↓ Enumerate query: foreach(var a in query) ↓ Current source data is observed! The new article IS included!

While deferred queries do not execute until enumeration, different operators behave differently when enumeration finally happens:

  • Streaming behavior: Operators like Where, Select, Skip, and Take process and yield elements one-by-one as they enumerate the source.
  • Buffering behavior: Operators like OrderBy and GroupBy must consume significant (or all) input elements before they can produce their first result (e.g., you can't know what the alphabetically first item is until you look at all of them).

18. Immediate vs Deferred Execution

Deferred Operators (Wait to run)Immediate/Terminal Operators (Run now)
Where, Select, OrderBy, GroupBy, Skip, Take, SelectManyToList, ToArray, Count, First, Any, Max
Multiple Enumeration

If you have a deferred query and you do:
int count = query.Count();
Article first = query.First();
The query is enumerated separately twice. Count() generally needs to inspect all matching elements, while First() can stop early. Still, if the query is expensive, hitting the database, or doing heavy math, you want to avoid enumerating it twice.

19. Materialization (Executing the Query)

Usually, you want to delay materialization until you actually need it. However, materializing earlier using ToList() or ToArray() can be intentional when you need a snapshot, need a concrete collection to mutate, or want to avoid repeated enumeration.

var query = articles.Where(a => a.Status == EnmArticleStatus.Published);

// Materializes the query ONCE into memory
List<Article> snapshot = query.ToList(); 

int count = snapshot.Count; // fast
Article first = snapshot.First(); // fast

20. Query Syntax vs Method Syntax

Everything you've learned so far is Method Syntax. LINQ also offers Query Syntax, which is translated into method-call-based LINQ operations behind the scenes.

// Method Syntax
var published = articles
    .Where(a => a.Status == EnmArticleStatus.Published)
    .OrderByDescending(a => a.ViewCount)
    .Select(a => a.Title);

// Query Syntax (Equivalent in behavior to the method syntax above)
var published = from a in articles
                where a.Status == EnmArticleStatus.Published
                orderby a.ViewCount descending
                select a.Title;

21. IEnumerable<T> vs IQueryable<T>

This is the secret to how LINQ connects to databases.

IEnumerable ↓ C# code operates over objects/data in memory. Delegates are compiled executable code. IQueryable ↓ Expression Tree describing a query. ↓ Provider may translate it. ↓ External data source (e.g. SQL Database).

With EF Core, LINQ operations that the provider can translate are normally converted into SQL and executed by the database, allowing filtering/projection to happen in the database instead of first loading all rows into application memory. (Note: Not every arbitrary C# expression can necessarily be translated by every provider).

Understanding this boundary is critical for performance:

// 1. IQueryable: Query can continue being translated into SQL by the provider
var query = dbContext.Articles.Where(a => a.ViewCount > 100);

// 2. AsEnumerable: Subsequent LINQ-to-Objects operations happen in application memory
var memoryQuery = dbContext.Articles.AsEnumerable().Where(a => a.ViewCount > 100);

// 3. ToList: Query executes immediately and results are materialized into memory
var list = dbContext.Articles.ToList();
Expression Trees Conceptually A Delegate is executable code. An Expression<Func<T, bool>> is a data structure (a tree) that describes code. A database provider inspects the tree (e.g., "Ah, they want Property 'Status' == 'Published'") and converts that description into a SQL WHERE clause.

22. Practical Mistakes & Performance Guidance

1. Confusing Where() and Select()
Where filters rows. Select shapes columns. Don't try to change the object shape inside a Where clause.
2. Calling First() when empty
If a list might be empty, use FirstOrDefault(), then check if the result is default.
3. Using Single() when multiple items exist
Single asserts EXACTLY ONE item matches. If two match, it throws. Use First() if you just want the first one.
4. Confusing Count() with Any()
Need the number? → Count()
Only need existence? → Any().
Precision Note: If the underlying source implements ICollection<T> (like a List<T>), Count() is an O(1) fast property lookup. However, if applied to a deferred LINQ query (e.g., after a Where), Count() must fully traverse and evaluate the entire remaining sequence. Any() strictly halts evaluation the millisecond the first match is found, making it vastly superior for existence checks on queries.
5. Calling ToList() too early
dbContext.Articles.ToList().Where(...). The ToList() materializes the massive table into application memory BEFORE filtering. Put ToList() at the end.
6. Skip/Take without OrderBy
Databases do not guarantee order. Always apply deterministic ordering before pagination for stable results.
7. Forgetting FirstOrDefault() can return null
Blindly chaining off it like articles.FirstOrDefault(x).Title will throw a NullReferenceException if the item isn't found.
8. Modifying a collection while enumerating it
You cannot add/remove items from a List inside a foreach loop enumerating that same list. Materialize a snapshot first if you must.

23. Complete Knowledge Base LINQ Demo

A full program combining the vast majority of LINQ operators into practical queries.

C# - Program.cs
using System;
using System.Collections.Generic;
using System.Linq;

namespace KnowledgeBase 
{
    public enum EnmArticleStatus { Draft, Published }

    public class User { public int Id { get; set; } public string Name { get; set; } }

    public class Article 
    {
        public int Id { get; set; }
        public string Title { get; set; }
        public int AuthorId { get; set; }
        public EnmArticleStatus Status { get; set; }
        public int ViewCount { get; set; }
        public List<string> Tags { get; set; } = new List<string>();
    }

    class Program 
    {
        static void Main() 
        {
            var users = new List<User> {
                new User { Id = 1, Name = "Alice" },
                new User { Id = 2, Name = "Bob" }
            };

            var articles = new List<Article> {
                new Article { Id = 10, Title = "C# Basics", AuthorId = 1, Status = EnmArticleStatus.Published, ViewCount = 500, Tags = new List<string>{"C#", "Beginner"} },
                new Article { Id = 11, Title = "LINQ Guide", AuthorId = 1, Status = EnmArticleStatus.Draft, ViewCount = 0, Tags = new List<string>{"C#", "LINQ"} },
                new Article { Id = 12, Title = "SQL Tips", AuthorId = 2, Status = EnmArticleStatus.Published, ViewCount = 1200, Tags = new List<string>{"SQL"} }
            };

            // 1. Where, OrderByDescending, ThenBy, Select, ToList (Chaining)
            var report = articles
                .Where(a => a.Status == EnmArticleStatus.Published)
                .OrderByDescending(a => a.ViewCount)
                .ThenBy(a => a.Title)
                .Select(a => new { a.Title, a.ViewCount })
                .ToList();

            // 2. SelectMany, Distinct, Concat
            var extraTags = new List<string> { "Advanced", "C#" };
            var allUniqueTags = articles
                .SelectMany(a => a.Tags)
                .Concat(extraTags)
                .Distinct()
                .ToList();

            // 3. Aggregation (Count, Max, Average, Any, All)
            bool hasPublished = articles.Any(a => a.Status == EnmArticleStatus.Published);
            int totalDrafts = articles.Count(a => a.Status == EnmArticleStatus.Draft);
            int maxViews = articles.Max(a => a.ViewCount);
            
            // 4. GroupBy vs ToLookup
            var groupedByStatus = articles
                .GroupBy(a => a.Status)
                .Select(g => new { Status = g.Key, AvgViews = g.Average(a => a.ViewCount) })
                .ToList();

            var lookupByAuthor = articles.ToLookup(a => a.AuthorId);

            // 5. Join (Inner) & GroupJoin (Grouped Matching / Left Join Concept)
            var articleAuthors = articles.Join(
                users, a => a.AuthorId, u => u.Id,
                (a, u) => $"{a.Title} by {u.Name}"
            ).ToList();
            
            var authorsWithArticles = users.GroupJoin(
                articles, u => u.Id, a => a.AuthorId,
                (u, aList) => new { Author = u.Name, ArticleCount = aList.Count() }
            ).ToList();

            // 6. Pagination & FirstOrDefault
            var firstPage = articles.OrderBy(a => a.Id).Skip(0).Take(2).ToList();
            var missing = articles.FirstOrDefault(a => a.Id == 999); // Returns null

            // Output Results
            Console.WriteLine($"Has Published: {hasPublished}, Drafts: {totalDrafts}, Max Views: {maxViews}");
            Console.WriteLine($"\nTags: {string.Join(", ", allUniqueTags)}");
            Console.WriteLine("\n--- Grouped By Status ---");
            groupedByStatus.ForEach(g => Console.WriteLine($"{g.Status}: {g.AvgViews} avg views"));
            Console.WriteLine("\n--- Join Result ---");
            articleAuthors.ForEach(Console.WriteLine);
            
            Console.ReadLine();
        }
    }
}

LINQ Operator Map (Mental Model)

Where → Which items? Select → What should each item become? SelectMany → Flatten nested collections OrderBy / ThenBy → How should items be sorted? GroupBy → How should items be grouped? Join → Which items from two sequences match? Any → Does at least one exist? All → Do all satisfy the condition? First → Give me the first Single → There must be exactly one Skip / Take → Which portion? Distinct → Remove duplicates Aggregate → Calculate a result (Count, Sum, Min, Max, Average) ToList / ToArray / ToDictionary / ToHashSet → Materialize the sequence

0b. Explain the behavioral difference between an `IQueryable` query and an `IEnumerable` query.
An `IEnumerable` query executes C# delegates in application memory. An `IQueryable` query builds an expression tree that a provider (like EF Core) translates into a native query (like SQL) to be executed by the database.

articles.ToDictionary(a => a.Id)

from a in articles where a.Id == 1 select a.Title

Output Prediction

1. `articles.Where(a => false).Count()`
0
2. `articles.Where(a => false).First()`
Exception (InvalidOperationException)
3. `articles.Where(a => false).FirstOrDefault()`
`null` (default for a reference type like Article)
4. `articles.Take(5).Skip(2).Count()` (Assuming 10 articles exist)

Find the Error

1. `var first = articles.First(a => a.Id == -99);` (Assume no such ID exists)
Error: `First()` throws an exception if no item matches. Use `FirstOrDefault()` if a miss is expected.
2. `var titles = articles.Select(a => a.Title).Where(a => a.ViewCount > 10);`
Error: Once you `Select(a => a.Title)`, the sequence becomes strings. Strings don't have a `ViewCount`. You must `Where` BEFORE you `Select`.
3. `articles.OrderBy(a => a.Status).OrderBy(a => a.Title)`
Error: The second `OrderBy` establishes a new primary sort, destroying the first. Use `.ThenBy(a => a.Title)`.
4. `var page = articles.Skip(10).Take(10).ToList();`
Error: Pagination without `OrderBy` is dangerous. The data order is not guaranteed. Always `OrderBy` first.
5. `var dict = articles.ToDictionary(a => a.AuthorId);`
Error: If multiple articles have the same AuthorId, this throws an exception because Dictionary keys must be unique. `ToLookup` is better here.

Interview Questions

1. What is the difference between IEnumerable and IQueryable?
IEnumerable represents an in-memory sequence of data, executing LINQ delegates via C#. IQueryable represents a query expression tree, typically translated by a provider (like Entity Framework) into SQL to run on a database.
2. What is Deferred Execution?
The concept where building a LINQ query does not actually execute it or fetch data. The query only executes when it is enumerated (e.g., via foreach or ToList).
3. Explain FirstOrDefault() vs SingleOrDefault().
Both return default (null) if no match is found. However, `FirstOrDefault()` simply returns the first match if there are multiple. `SingleOrDefault()` enforces uniqueness; if multiple matches exist, it throws an exception.
4. How does Distinct() determine if objects are equal?
Distinct uses equality comparison. For primitive types it compares values. For custom objects, if value-based equality isn't defined, separate objects with identical property values are treated as different objects based on reference equality.
5. When should you use Any() instead of Count() > 0?
When you only need to know whether something exists. `Any()` can often stop as soon as it finds a matching element, whereas `Count()` may need to iterate the entire collection. `Any()` also communicates intent more clearly.
