Top-Level Statements vs Traditional Main

Difficulty: Beginner | Category: Deep Dives (Custom)

The Beginner's Mental Model

Imagine you want to send a text message that says "Hello".

Traditional C# forces you to write a formal letter: You must write an envelope (Namespace), a formal letterhead (Class), and a signature (static void Main) just to send "Hello".
Top-Level Statements (C# 9+) let you just send the text message. The compiler secretly writes the envelope and letterhead for you behind the scenes.

A. The Core Problem: Boilerplate Fatigue

For 20 years, every C# program, no matter how tiny, required at least 11 lines of code just to run. This confused beginners and cluttered modern web applications. In C# 9, Microsoft introduced Top-Level Statements to strip away the "ceremony" and expose only the logic that matters.

What the Compiler Deletes for You
using System;

namespace KnowledgeBase.App
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello World");
        }
    }
}

COMPLETE EXAMPLE 1: Basic vs Modern

Here is the exact same program written both ways. Notice how much faster it is to read the modern approach.

C# - Traditional Program.cs
using System;

namespace KnowledgeBase.Legacy
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("This is the traditional, verbose way.");
        }
    }
}
C# - Modern Top-Level Program.cs
// This is the ENTIRE file!
Console.WriteLine("This is the modern, top-level way.");

COMPLETE EXAMPLE 2: Applied (Simple Script)

Top-Level statements are great for short, simple scripts. Here is a complete program that reads what the user typed in the console and creates a mock article, all without needing a traditional Class or Main method.

C# - Simple Top-Level Script
using System;

// 1. TOP-LEVEL EXECUTION (No Main, No Class)
Console.WriteLine("Welcome to the Knowledge Base Setup!");

// We can magically access 'args' if the user passed command line arguments
if (args.Length > 0)
{
    Console.WriteLine("Starting in mode: " + args[0]);
}

// We can call methods that are defined at the bottom of the file
PrintArticleInfo("Learning C#");


// 2. METHODS (Must be placed at the bottom of the file)
void PrintArticleInfo(string title)
{
    Console.WriteLine("Generating article placeholder for: " + title);
}
The One Golden Rule

You can only have ONE file in your entire project that uses Top-Level Statements. Because the compiler is secretly building a static void Main() for you, if you put top-level statements in two different files, the compiler will try to create two Main() methods, and your program will crash. Keep it strictly in Program.cs!
