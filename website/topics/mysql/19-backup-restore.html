19. Backup & Restore (Logical vs Physical)

Admin & Internals

Backup & Restore Strategies

A senior database engineer must understand the internal difference between a Logical Backup and a Physical Backup, and how GUI tools abstract these operations.

Logical vs Physical Backups

Concept Logical Backup (mysqldump / Workbench) Physical Backup (Percona XtraBackup / LVM)
What is backed up? SQL statements (CREATE TABLE, INSERT INTO). Raw binary disk files (.ibd, redo logs, undo logs).
Portability Extremely high. You can restore an 8.0 backup into 8.4, or even to MariaDB. Extremely strict. Must restore to the exact same MySQL major/minor version and OS architecture.
Speed Slow. The DB must parse the SQL and execute massive INSERT statements through the Buffer Pool. Instantaneous. You are just copying raw OS files block-by-block.

MySQL Workbench GUI Mapping

When you click through the Administration → Data Export tab in MySQL Workbench, you are not using a magical GUI feature. Workbench is simply building a command-line string and executing mysqldump.exe in the background.

  • "Dump Structure and Data": Executes standard mysqldump. Results in CREATE TABLE followed by INSERT INTO.
  • "Dump Structure Only": Appends the --no-data flag. It only queries the Data Dictionary for schemas. Useful for duplicating environments.
  • "Dump Data Only": Appends the --no-create-info flag. Bypasses DDL. Useful for refreshing staging environments where the schema is already migrated.
  • "Include Create Schema": Appends the --databases flag, inserting CREATE DATABASE IF NOT EXISTS into the output file.
  • "Dump Stored Routines / Events / Triggers": Appends the --routines, --events, and --triggers flags. (Important: Triggers are dumped by default, but routines and events are not!).
