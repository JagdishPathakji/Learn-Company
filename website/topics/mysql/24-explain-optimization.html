24. EXPLAIN & Optimizer Tuning

Admin & Internals

The EXPLAIN Keyword

EXPLAIN allows you to peek into the MySQL Optimizer's chosen execution plan. EXPLAIN ANALYZE (introduced in MySQL 8.0.18) actually executes the query and provides the physical time spent in each iterator.

Interpreting Access Methods (The 'type' column)

When reading an EXPLAIN output, the type column indicates how the Execution Engine accessed the rows. From fastest to slowest:

  • system / const: The table has exactly one row, or you queried a Primary Key with a literal equality. (Instant lookup).
  • eq_ref: A Primary Key or Unique index was used in a JOIN.
  • ref: A non-unique Secondary Index was used for an equality lookup.
  • range: An index was used, but to retrieve a range of rows (e.g., BETWEEN, >).
  • index: A Full Index Scan. The engine scanned the leaf nodes of the B+Tree sequentially, but didn't read the physical table rows.
  • ALL: A Full Table Scan. The engine read every physical page of the table from disk into the Buffer Pool. (Catastrophic for large tables).
