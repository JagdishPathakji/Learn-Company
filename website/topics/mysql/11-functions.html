11. Functions & Determinism

Advanced SQL

Functions in MySQL

MySQL provides Built-in Functions (e.g., NOW(), UPPER()) and allows creation of Stored Functions. The most critical internal aspect of functions is not their syntax, but how they interact with Indexes and how their Determinism affects query execution plans.

Functions in the WHERE Clause (Sargability)

A query is "sargable" (Search Argument Able) if the Optimizer can use an index to satisfy the WHERE clause.

The Index Annihilation Rule

Wrapping an indexed column inside a function immediately prevents the Optimizer from using the B+Tree index for access.

-- Fast: Uses index
SELECT * FROM users WHERE created_at = '2026-01-01';

-- Slow: Full Table Scan
SELECT * FROM users WHERE DATE(created_at) = '2026-01-01';

Why? The B+Tree is sorted based on the raw, literal values of created_at. It is not sorted by the output of the DATE() function. The Execution Engine is forced to read every single row in the table, calculate DATE() for that row in CPU memory, and then compare it to the literal.

Solution: Always rewrite queries so the column is isolated on one side of the operator: WHERE created_at >= '2026-01-01 00:00:00' AND created_at < '2026-01-02 00:00:00'.

Deterministic vs Non-Deterministic Functions

When creating a Stored Function, you must declare it as DETERMINISTIC or NOT DETERMINISTIC. This is not just documentation; it drastically alters Optimizer behavior.

  • DETERMINISTIC: The function always returns the exact same output for the same input. (e.g., UPPER(string)). The Optimizer can cache the result. If a query calls it 10,000 times with the same input, MySQL calculates it once.
  • NOT DETERMINISTIC: The output can change (e.g., NOW(), RAND(), or querying a table). The Execution Engine must physically execute the function for every single row it processes.
