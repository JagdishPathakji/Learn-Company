23. Transactions & Isolation Levels

Admin & Internals

Transactions and ACID

A transaction is a logical unit of work. In InnoDB, it guarantees the ACID properties: Atomicity, Consistency, Isolation, and Durability.

Isolation Levels & MVCC

InnoDB uses MVCC (Multi-Version Concurrency Control) and Locks to enforce Isolation.

Isolation Level Internal Behavior (InnoDB)
READ UNCOMMITTED Ignores MVCC. Reads the dirty, uncommitted pages directly from the Buffer Pool. Causes "Dirty Reads".
READ COMMITTED Uses MVCC. Every single query inside the transaction generates a new snapshot. You only see committed data, but running the exact same SELECT twice might yield different results if another transaction committed in between.
REPEATABLE READ (Default) Uses MVCC. The snapshot is created on the first query and held for the entire transaction. Running the same SELECT 100 times will return the exact same data, reading from the Undo Logs to bypass any concurrent modifications.
SERIALIZABLE Abandons MVCC. Converts all standard SELECTs into SELECT ... FOR SHARE. Places read locks on every row accessed, forcing concurrent writers to wait. Eliminates all concurrency.
