Stored Procedure Parameters and Working

Stored Procedures allow you to encapsulate complex business logic, multiple queries, and transaction management inside the MySQL Server. Understanding how data flows into, out of, and within a procedure requires mastering Parameters and Variables.

Procedure Parameters (IN, OUT, INOUT)

Parameters define the contract between the caller and the procedure.

Direction Behavior Use Case
IN (Default) Passes a value into the procedure. The procedure can modify it internally, but the caller will not see the change. Providing IDs, thresholds, or search strings.
OUT Passes a value out of the procedure. The initial value provided by the caller is ignored (set to NULL). When the procedure finishes, the final value is copied back to the caller's variable. Returning counts, generated IDs, or status codes.
INOUT A combination. The caller passes a value in, the procedure modifies it, and the caller receives the modified value back. Counters, string formatting accumulators.

Execution Lifecycle Example

-- Defining the Procedure
CREATE PROCEDURE ProcessOrder(
    IN p_order_id INT,
    OUT p_status VARCHAR(20)
)
BEGIN
    -- Local Variable Declaration
    DECLARE v_total DECIMAL(10,2);
    
    -- Querying into the Local Variable
    SELECT total_price INTO v_total
    FROM orders WHERE id = p_order_id;
    
    -- Logic
    IF v_total > 1000 THEN
        SET p_status = 'High Value';
    ELSE
        SET p_status = 'Standard';
    END IF;
END;

What happens during execution?

CALL ProcessOrder(105, @final_status);
SELECT @final_status;
  1. The caller executes CALL, passing the literal 105 to p_order_id, and binding the User Variable @final_status to p_status.
  2. The procedure allocates memory for the Local Variable v_total.
  3. The SELECT ... INTO statement is optimized and executed, fetching the row from the Buffer Pool, and storing the price in v_total.
  4. The IF condition evaluates. The OUT parameter p_status is updated in the procedure's memory context.
  5. The procedure finishes. The MySQL Server takes the value of p_status and explicitly copies it into the caller's session User Variable @final_status.
  6. The caller runs SELECT @final_status; to view the result.

Variables Comparison

  • Local Variable (DECLARE v_name INT;): Strictly scoped to the BEGIN...END block. Dropped from memory the millisecond the procedure ends. Requires no @ symbol.
  • User Variable (SET @v_name = 1;): Scoped to the entire Client Session. It persists across multiple queries and procedure calls until the connection drops.
  • System Variable (@@global.max_connections): Defines the configuration of the MySQL Server daemon itself.
